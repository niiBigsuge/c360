## 1. Executive Summary
**TheCrown360**, a Hair Salon Booking & Home Service Platform, is a premium web application designed to convert visitors into confirmed appointments. It allows customers to browse popular hairstyles, select a look, and seamlessly book either an in-salon visit or a mobile home service. The platform focuses on a high-end visual experience and an frictionless booking flow, featuring a "pay after service" model to reduce booking friction. The MVP serves as a robust landing page and booking engine, with architecture designed to support a full administrative dashboard in the future.

## 2. Core Workflows (The Happy Path)
- **Workflow 1: Browsing and Selection**: A prospective customer lands on the site, views high-quality hero imagery, and browses the "Trending Looks" or "Services" section. They click "Book This Style" on a specific hairstyle (e.g., Knotless Braids).
- **Workflow 2: Booking an In-Salon Appointment**: The customer selects "In-Salon", chooses an available date and time from the calendar widget, enters their personal details (Name, Phone, Email), and confirms the booking. They receive a success confirmation.
- **Workflow 3: Booking a Home Service**: The customer selects "At Home", enters their precise location (which triggers a transportation fee calculation based on predefined rules or flat rates), picks an available date and time, enters their personal details, and confirms the booking.
- **Workflow 4: Service & Payment Fulfillment**: The stylist performs the service (either in-salon or at home), and the customer pays upon completion. (Note: Handled offline in the MVP).

## 3. Architecture & Tech Stack
- **Frontend**: Next.js 14 App Router, React, TypeScript, Tailwind CSS, shadcn/ui. (For UI design, strictly follow `design.md`).
- **Backend**: Next.js Server Actions / API Routes.
- **Database**: PostgreSQL (via Servbay) for storing hairstyles, bookings, and customer data.
- **Authentication**: Custom Authentication (e.g., Auth.js / NextAuth backed by Servbay PostgreSQL) with immediate support for Admin accounts and guest checkout for MVP bookings.
- **Infrastructure**: Vercel for fast, edge-optimized hosting.
- **Key Dependencies**: React Hook Form + Zod for robust form validation, Date-fns/Day.js for calendar manipulation.

## 4. Edge Cases & Error Handling
| Scenario | Expected System Behavior |
|----------|--------------------------|
| **Double Booking / Race Condition** | Two users book the same slot simultaneously. The database strictly enforces unique constraints on (date, time, stylist_id). The second user gets a graceful error: "This slot was just taken. Please select another." |
| **Out-of-Range Home Service Location** | User requests home service outside the salon's operating region. The form validates the location (e.g. by city or distance) and rejects the booking with a polite message. |
| **No-Show Prevention / Spam Bookings** | Since there is no upfront payment, a malicious user could spam bookings. MVP will require basic phone/email validation. Future state: OTP verification via SMS/WhatsApp. |
| **Database Connection Fails** | Supabase goes down. User sees a styled 503 error page or a toast notification: "Unable to complete booking at this time, please call [Phone Number]." |
| **User Refreshes During Booking** | Booking state is held in React state/Context. If refreshed before confirmation, they restart the flow. (Since it's a short flow, this is acceptable for MVP). |

## 5. Non-Functional Requirements
- **Performance**: High-quality images must be heavily optimized (Next.js Image component, WebP) to ensure Core Web Vitals (LCP) remain under 2.5s.
- **Design Aesthetic**: Premium beauty/fashion aesthetic—elegant typography, large high-resolution photography, rounded cards, smooth scrolling, and subtle view transitions. Mobile-first execution is critical.
- **Security**: Native PostgreSQL Row Level Security (RLS) via Servbay must ensure public users can only *insert* bookings but not read other people's bookings.
- **Scale**: Initial architecture should support up to 500 concurrent visitors and 100+ daily bookings without latency spikes.

## 6. Resolved Requirements (From Open Questions)
- **Home Service Boundaries**: The user's location will be collected via a text field during booking. The admin will manually verify the location to confirm if it falls within the acceptable travel radius.
- **Transportation Fee Logic**: The transportation fee will be dynamically calculated as exactly 15% of the actual price of the hairstyle selected or booked. This fee must be explicitly included in the final total amount displayed to the customer.
- **Stylist Availability**: The system will assume a generic salon capacity (e.g., "We can take 3 bookings at 10:00 AM") rather than tracking individual stylists' schedules for the MVP.
- **Notifications**: Yes, the MVP will send an automated email confirmation to the customer upon booking. (This will be implemented using Resend or a similar transactional email provider).
